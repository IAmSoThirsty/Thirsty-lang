  [ ] Run Python lint, type, security, package, and full-suite gates.
  [ ] Build the local image and run --version plus run --demo.
  [ ] Run docker compose config --services and confirm exactly 8 services.
  [ ] Run docker compose run --rm test.
  [ ] Commit and push the cohesive release state.
  [ ] Wait for branch CI to pass.

2. TAG THE VERIFIED COMMIT
  git tag -a v<version> -m "Thirsty-Lang <version>"
  git show --no-patch --decorate v<version>
  git push tp refs/tags/v<version>

  A lowercase v* tag starts both PyPI and Docker release workflows.
  A docker-v* tag is for an explicitly intended Docker-only publication.

3. MONITOR GITHUB ACTIONS
  https://github.com/IAmSoThirsty/Thirsty-lang/actions

  [ ] Branch CI passed for the tagged commit.
  [ ] PyPI release workflow passed for a normal v* release.
  [ ] Docker workflow passed.
  [ ] GHCR pull, version, and demo verification steps passed.

4. VERIFY THE PUBLISHED ARTIFACTS
  [ ] Fresh Python 3.11 environment installs thirsty-lang==<version> from PyPI.
  [ ] Release-specific regression matrix passes against that installed wheel.
  [ ] docker pull ghcr.io/iamsothirsty/thirsty-lang:<version> succeeds.
  [ ] Container --version and run --demo succeed.
  [ ] docker buildx imagetools inspect lists linux/amd64 and linux/arm64.
  [ ] Record the GHCR manifest digest.

5. RECORD EVIDENCE
  [ ] Release commit SHA and annotated tag object SHA.
